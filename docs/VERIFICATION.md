Тесты миграции выполнялись через реальный PostgreSQL-движок в WASM (PGlite) и asyncpg. Обычные регрессионные тесты используют временную SQLite и подменённые Telegram-клиенты. PGlite не заменяет проверку обычного PostgreSQL под нагрузкой; для PostgreSQL 16 подготовлен отдельный CI. Для одноразового PGlite при тестах использовался режим без SQL-очистки схем в teardown: весь временный процесс БД уничтожался по окончании прогона. Этот режим не используется в приложении.

## Проверенные сценарии

- Групповой чат, неавторизованный и прежний владелец не получают доступ; менеджер не запускает команды владельца.
- Ограничение каналов работает в списке, старых кнопках и сервисе запуска. Ранее полные права менеджера остаются поведением по умолчанию.
- Одновременные действия одного аккаунта сериализуются; отмена во время захвата блокировки не теряет слот; отключение прерывает работающие и ожидающие операции.
- Обязательный прокси не заменяется прямым выходом; назначение стабильно, отказ закреплённого прокси останавливает подключение; FloodWait сохраняется.
- Полный план записывается до старта; повреждённая сессия видна в результатах; общая пауза переживает перезапуск и блокирует расписания.
- Штатное завершение сохраняет 24/7 и контрольные точки; тест посещает все каналы, обрабатывает порции и завершает дедлайн без ложной пользовательской отмены.
- Смена Telegram ID канала обнаруживается до регистрации просмотров; пауза канала проверяется перед порцией.
- TXT/JSON/SQLite/ZIP, пары tpanel `.session + .json`, объединение повторов, запрет опасных путей и лишних форматов, размеры, сроки предпросмотра, проверка владельца, частичный результат и очистка исходного материала.
- Присланный контрольный архив распознан как 37 уникальных записей: 0 готовых сессий и 37 QR-подтверждений, поскольку все 37 файлов `.session` имеют нулевой размер. Телефонные номера и секретные поля в вывод тестов не попадали.
- Сквозной путь через aiogram: меню → список номеров → предпросмотр → подтверждение → результаты. QR + 2FA проверены с подменёнными ответами Telegram; сообщение с паролем удаляется до его передачи клиенту.
- XLSX не превращает названия в формулы, имеет приватные права; архивирование сохраняет исторические данные; продление не меняет дату завершения.
- Резервная копия публикуется после проверки; неудача сохраняет предыдущую копию и дату успеха; проверена блокировка копирования и очистка промежуточных файлов age-зеркала. Процессы pg_dump/age в этих тестах подменены.

## Что требуется при развёртывании

Не выполнялись вход с настоящим аккаунтом Telegram, проверка ваших реальных прокси, установка systemd на вашем сервере, нагрузочный тест общего PostgreSQL и полное восстановление настоящего дампа через системный pg_restore. Эти действия требуют ваших реквизитов, сервера и реальных данных.

В пакет включены read-only `doctor.py`, команда копирования, скрипт полного восстановления в отдельную тестовую БД и инструкции по безопасному переносу. Внешнее хранилище/закрытый ключ age не создавались: это параметры инфраструктуры, которые задаются при установке. Нулевой результат pip-audit не является гарантией отсутствия всех возможных уязвимостей; проверка касается опубликованных сведений о зафиксированных пакетах на указанную дату.
