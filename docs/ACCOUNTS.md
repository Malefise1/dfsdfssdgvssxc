# Добавление аккаунтов в боте

Доступно только главному администратору и только в личном чате. Одновременно работает одна очередь добавления. Настройки и результаты доступны в «Аккаунты → Добавить аккаунты».

## Один аккаунт

Выберите «Один аккаунт · QR», затем «Показать QR». В нужном аккаунте Telegram откройте «Настройки → Устройства → Подключить устройство» и отсканируйте код с другого экрана. QR обновляется автоматически; на один аккаунт по умолчанию отводится 5 минут. После успешной авторизации бот удаляет QR-сообщение и сохраняет зашифрованную сессию.

Вместо QR можно загрузить один готовый файл Telethon `.session`. Добавление по номеру также использует QR для подтверждения именно этого номера. Передача одноразового кода Telegram сообщением боту не используется.

## Несколько аккаунтов

| Способ | Содержимое |
|---|---|
| ZIP | Один или несколько файлов Telethon `.session`, JSON или TXT; также пары `<номер>.session` + `<номер>.json` из tpanel.online; без вложенных архивов и посторонних файлов |
| TXT | По одной `StringSession` или номеру `+79991234567` на строку, UTF-8 |
| JSON | Массив объектов или `{"accounts":[...]}`; в каждом объекте поле `session`, `string_session` либо `phone` |
| Список в сообщении | Номера в международном формате, по одному на строку |

Примеры без настоящих учётных данных: `examples/phones.txt`, `examples/accounts.json`. Для JSON с готовой сессией используйте объект `{"session":"ВАША_STRING_SESSION_TELETHON"}`. Надпись-заполнитель не является рабочей сессией.

Лимиты по умолчанию: 100 аккаунтов, загрузка до 5 МБ, общий распакованный размер до 20 МБ, отдельный файл в ZIP до 2 МБ. Парные экспорты могут содержать до двух файлов на аккаунт; лимит применяется к найденным аккаунтам, а не к числу файлов. `.session` с готовой авторизацией должен содержать ключ и публичный адрес сервера. Если в парном экспорте `.session` пустая или отсутствует, бот безопасно использует номер из JSON и запросит QR-подтверждение: импортировать готовую авторизацию из нулевого файла технически невозможно. ZIP с путями выхода из каталога, символьными ссылками, паролем или чрезмерной степенью сжатия отклоняется. Форматы Telegram Desktop `tdata` и сессии других библиотек не поддерживаются.

Перед началом бот показывает количество готовых сессий и необходимых QR-подтверждений. Повторяющиеся записи внутри файла объединяются. Уже известный ключ сессии не открывается повторно. Если другой ключ ведёт к уже добавленному аккаунту, запись отмечается как дубликат.

Готовые сессии проверяются по очереди. Для списка номеров бот последовательно показывает QR каждого аккаунта; вход всё равно требует согласия владельца каждого номера. Кнопки «Пропустить аккаунт» и «Остановить импорт» доступны по ходу работы. Результат каждого элемента и ошибки доступны в истории импорта и XLSX. После перезапуска незавершённый импорт помечается прерванным; его исходные секреты не восстанавливаются с диска.

## Пароль 2FA и файлы сессий

Файл сессии и QR для входа дают доступ к аккаунту. Не пересылайте их и используйте только свои аккаунты либо аккаунты с явным разрешением владельцев.

Если Telegram требует пароль 2FA, бот запрашивает его отдельно. Сообщение удаляется **до проверки пароля**; если удаление не удалось, пароль не принимается. Пароль остаётся только в памяти текущей попытки, не помещается в FSM, базу, результаты импорта или журналы. Есть ограничение времени и трёх попыток. Входящий файл удаляется перед загрузкой его содержимого в память.

Удаление сообщения не превращает обычный чат бота в чат со сквозным шифрованием и не гарантирует отсутствие копий у Telegram или на клиентском устройстве. Для передачи готовых сессий без чата есть локальная команда при остановленной службе:

```bash
TGVIEWER_ENV_FILE=/etc/tgviewer2/app.env /opt/tgviewer2/current/.venv/bin/python \
  /opt/tgviewer2/current/manage.py import-local /защищённый/каталог/accounts.zip
```

Запускайте её от пользователя службы; путь к файлу должен быть ему доступен. Команда не удаляет исходник: после проверки результата уберите его из временного каталога. Одновременный запуск с ботом блокируется.

## Повторный вход и удаление

«Войти заново» останавливает аккаунт и проверяет, что подтверждён тот же Telegram ID. При неудачной повторной авторизации аккаунт остаётся выключенным до исправления. Новый ключ публикуется в базе только после закрытия соединения авторизации.

«Удалить из работы» прекращает текущие операции, удаляет локальную зашифрованную сессию и архивирует запись. Номер аккаунта остаётся зарезервированным, история отчётов сохраняется. Для отзыва ключа у Telegram отдельно завершите соответствующий сеанс в «Устройствах».
