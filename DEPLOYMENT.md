# Установка рядом с другими проектами

Целевая конфигурация: Ubuntu 24.04, Python 3.12, PostgreSQL 16+ и systemd. Перед установкой нужно проверить текущие службы, свободные память/диск и используемый кластер PostgreSQL. Пакет сам не устанавливает и не обновляет системные пакеты.

## Что будет создано

Для имени `tgviewer2`:

| Ресурс | Значение |
|---|---|
| Системный пользователь и группа | `tgviewer2`, без интерактивного входа |
| Служба | `tgviewer2.service` |
| База и роль PostgreSQL | `tgviewer2`; роль без SUPERUSER/CREATEDB/CREATEROLE, лимит 15 соединений |
| Код и окружение Python | `/opt/tgviewer2/releases/<дата>`, ссылка `/opt/tgviewer2/current` |
| Настройки | `/etc/tgviewer2/app.env`, `root:tgviewer2`, режим 0640 |
| Данные, отчёты, копии | `/var/lib/tgviewer2`, режим 0700 |
| Логи | `/var/log/tgviewer2`, ротация 5 × 5 МБ |
| Ресурсы процесса | CPU 50% одного ядра, MemoryHigh 512 МБ, MemoryMax 768 МБ, 128 задач |

Бот использует исходящие подключения и long polling. Входящий HTTP-порт, домен, Nginx и изменения firewall ему не нужны. Имена занятых пользователей, каталогов, ролей, баз и служб установщик не переиспользует. Для другого экземпляра укажите, например, `--instance tgviewer_tools`.

Установщик не выполняет `apt upgrade`, не меняет конфигурацию общего PostgreSQL, не перезапускает его и не управляет чужими systemd-службами. `daemon-reload` перечитывает определения служб без их перезапуска. Ограничения systemd относятся к процессам бота; общий PostgreSQL, диск и сеть остаются разделяемыми ресурсами. Абсолютная изоляция нагрузки требует отдельного контейнера/VM или отдельного кластера БД. На существующем сервере сначала оцените запас ресурсов.

## Подготовка

Проверьте наличие `python3.12`, модуля `venv`, `pg_dump`, `pg_restore`, `psql`, `runuser` и systemd. Версия PostgreSQL-клиента должна уметь читать используемый сервер (обычно клиент той же основной версии). Если пакетов не хватает, согласуйте их установку с конфигурацией сервера. В окружении с уже работающим PostgreSQL не устанавливайте другой кластер вслепую.

Распакуйте архив в отдельный каталог. Не копируйте его поверх работающей версии. Если переносите старый проект, сначала прочитайте [UPGRADE.md](UPGRADE.md).

## Новая установка

Из распакованного каталога:

```bash
sudo bash scripts/install_ubuntu.sh --instance tgviewer2 --pg-port 5432
```

Скрипт проверяет конфликты имён, создаёт отдельное окружение из зависимостей с хешами, пользователя, базу и настройки. Служба остаётся выключенной. Если установка прервана, не удаляйте каталоги/роль наугад: проверьте точную причину и созданные ресурсы этого экземпляра.

Введите токен и Telegram API-реквизиты без помещения секретов в историю shell:

```bash
sudo /opt/tgviewer2/current/.venv/bin/python \
  /opt/tgviewer2/current/manage.py configure /etc/tgviewer2/app.env
```

`MAIN_ADMIN_ID` — числовой Telegram ID владельца, не username. `API_ID` и `API_HASH` — реквизиты Telegram API вашего приложения. Не создавайте новые значения `SESSION_ENCRYPTION_KEY` при переносе существующей БД.

Затем из распакованного каталога:

```bash
sudo python3.12 scripts/deploy.py activate --instance tgviewer2
sudo systemctl status tgviewer2.service --no-pager
sudo journalctl -u tgviewer2.service -n 50 --no-pager
```

Проверьте `/start` в личном чате. Первый запуск находится на общей паузе. Настройте прокси, добавьте один аккаунт, выполните проверку соединения, затем снимите паузу и проведите короткий тест на одном канале. После этого загружайте остальные аккаунты. Если несколько процессов пытаются использовать одну базу или DATA_DIR, лишний процесс не запускается.

## Обслуживание

```bash
# Только чтение конфигурации/БД и проверка прав, без миграций:
sudo -u tgviewer2 env TGVIEWER_ENV_FILE=/etc/tgviewer2/app.env \
  /opt/tgviewer2/current/.venv/bin/python /opt/tgviewer2/current/doctor.py

# Резервная копия; допустима при работающем боте:
sudo -u tgviewer2 env TGVIEWER_ENV_FILE=/etc/tgviewer2/app.env \
  /opt/tgviewer2/current/.venv/bin/python /opt/tgviewer2/current/manage.py backup

# Перезапуск именно этого проекта:
sudo systemctl restart tgviewer2.service
```

Ресурсы можно изменить через `sudo systemctl edit tgviewer2.service`, добавив нужные `CPUQuota`, `MemoryHigh`, `MemoryMax` в `[Service]`. Не увеличивайте лимиты без проверки свободных ресурсов общего сервера. Фоновая задача проверяет аккаунты, соединения и копии; сбой задачи показывается в боте и уведомляет владельца не чаще раза в день.

## Резервные копии и внешний носитель

По умолчанию копия создаётся раз в три дня, хранится 20 последних. `pg_dump` пишет во временный файл; после успешного завершения `pg_restore --list` проверяет его каталог, затем файл атомарно переименовывается. Пароль БД передаётся в окружении дочернего процесса, а не в аргументах команды. Параллельные копии от бота и CLI блокируются.

Проверка каталога не заменяет восстановления. Выполните полный тест на отдельной автоматически созданной БД:

```bash
sudo python3.12 scripts/verify_restore.py \
  /var/lib/tgviewer2/backups/ИМЯ_КОПИИ.dump --port 5432
```

Скрипт создаёт БД `tgviewer_restore_test_<случайный суффикс>`, восстанавливает в неё дамп, проверяет чтение таблиц и удаляет только эту тестовую БД. Рабочую БД он не очищает. На большой базе тест создаёт дополнительную нагрузку и требует свободного места; выполняйте в подходящее время.

Для внешней копии поддержан **необязательный зашифрованный каталог**. Подготовьте внешний носитель/сетевой mount, установите `age` и задайте оба параметра в `app.env`:

```dotenv
BACKUP_MIRROR_DIR=/mnt/tgviewer-offsite
BACKUP_AGE_RECIPIENT=age1ВАШ_ПУБЛИЧНЫЙ_КЛЮЧ
```

Приватный ключ age храните отдельно от сервера. Добавьте каталог в `ReadWritePaths=` через drop-in службы; предоставьте доступ только пользователю `tgviewer2`. Бот сохраняет туда `.dump.age` через временный файл и удаляет устаревшие зашифрованные копии по тому же лимиту. При недоступности зеркала локальная копия сохраняется, ошибка видна в диагностике; следующая проверка повторяет отправку в каталог. Путь сам по себе не означает отдельный сервер: внешний носитель должен быть настроен вами. В этом пакете внешний адрес/ключ не заданы.

Сохраните отдельно защищённую копию `app.env`, особенно `SESSION_ENCRYPTION_KEY`. Без этого ключа восстановленные Telegram-сессии и пароли прокси не расшифровать. Не отправляйте конфигурацию или дампы в общие чаты. Полное восстановление age-копии: сначала расшифровать её на доверенной машине через `age --decrypt -i <закрытый_ключ>`, затем проверить обычный дамп указанной выше командой.
