# Патч 2.0.4 — удаление прокси

Для экземпляра `tgviewer2`: поддерживается патч 2.0.3 и присланная 17 октября сборка с входом по коду. Обновление накопительное: меню, исправления прокси и все способы добавления аккаунтов из 2.0.3 сохраняются.

## Установка

Загрузите `telegram-channel-viewer-patch-2.0.4.zip` в `/root` и выполните:

```bash
patch_dir=$(mktemp -d /root/tgviewer-patch.XXXXXX)
unzip /root/telegram-channel-viewer-patch-2.0.4.zip -d "$patch_dir"
python3 "$patch_dir/tgviewer-patch-2.0.4/update.py" --instance tgviewer2
systemctl status tgviewer2.service --no-pager
```

Затем отправьте боту `/menu`. Установщик работает с Python 3.10 и использует существующее окружение бота. Предыдущий релиз оставьте на месте: его `.venv` используется новой сборкой.

## Удаление

- Один прокси: «Прокси → карточка → Удалить».
- Часть: «Прокси → Удалить выбранные». Отмечайте нужные строки; выбор сохраняется между страницами. Можно выбрать всю страницу или снять выбор.
- Все: «Прокси → Удалить все».

Во всех случаях сначала появляется подтверждение с количеством прокси и связанных аккаунтов. Оно действует 5 минут. Отмена ничего не удаляет. Повторное нажатие старого подтверждения не повторяет операцию. Кнопки доступны только главному администратору.

«Удалить все» фиксирует список при показе подтверждения. Прокси, добавленные после этого, не удаляются. Во время добавления/повторного входа аккаунтов сначала завершите этот процесс, затем удаляйте прокси.

## Что происходит с аккаунтами

Текущие подключения через удаляемые прокси останавливаются. Активные привязанные аккаунты ставятся на паузу. Их номера, телефоны, зашифрованные сессии, ключ шифрования и подписки сохраняются. Состояние аккаунтов, уже требующих авторизации, не меняется.

Чтобы продолжить работу: добавьте и проверьте новый прокси, откройте «Аккаунты → аккаунт → Прокси», назначьте его и включите аккаунт. До назначения нового маршрута даже ручная проверка сессии не переходит автоматически на IP сервера. Карточка сообщает, что прежний прокси удалён.

Прокси удаляются из БД вместе с сохранёнными реквизитами. История заданий и результаты остаются; ссылка на удалённый прокси в результатах очищается. Ранее созданные резервные копии сохраняют прежние данные.

## Сохранность при обновлении

Установка сама по себе не удаляет прокси и не ставит аккаунты на паузу. Эти действия выполняются только кнопкой после подтверждения.

Установщик сверяет исходники с проверенной сборкой, создаёт отдельный релиз, резервную копию БД и закрытую копию настроек. До переключения сравниваются все поля аккаунтов и проверяется расшифровка сессий. Миграции схемы и повторное добавление аккаунтов не выполняются. При ошибке запуска возвращается предыдущий код. Исходно остановленная служба остаётся остановленной.

## Проверка

Локальные тесты проверяют выбор по страницам, отмену, повторные и устаревшие подтверждения, запрет удаления для менеджера, остановку живых подключений, сохранение сессий и отчётов, отсутствие автоматического перехода на другой маршрут и откат при ошибке БД. Реальные Telegram-аккаунты не используются. Проверки PostgreSQL требуют отдельного тестового сервера.

При ошибке пришлите вывод установки и при необходимости:

```bash
journalctl -u tgviewer2.service -n 60 --no-pager
```
