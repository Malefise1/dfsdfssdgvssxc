# Telegram Channel Viewer 2.0.1

Русскоязычный Telegram-бот для работы с публичными каналами через принадлежащие вам пользовательские аккаунты. Управление, добавление аккаунтов, расписания, состояние и отчёты доступны в личном чате с ботом.

## Что изменилось

- Аккаунты добавляются по одному через QR или массово: ZIP с `.session`, пары `.session + .json` из tpanel.online, JSON, TXT, список номеров. Пустые парные сессии переводятся в QR-подтверждение. Есть предпросмотр, проверка дубликатов, пропуск, отмена и история импорта с XLSX.
- Общая пауза и отмена заданий сохраняются в БД. Обычный перезапуск продолжает разрешённую работу с записанного прогресса.
- На один аккаунт приходится одно рабочее соединение. Проверки, подписки и задания используют общие ограничения. Прокси закрепляется; прямой выход по умолчанию запрещён.
- Отчёт учитывает весь запланированный состав аккаунтов и каналов. Тест обходит каналы порциями, даты завершения не меняются при продлении хранения, архивирование аккаунта сохраняет историю.
- Поиск, фильтры и страницы; редактирование расписаний; проверки аккаунтов; журнал действий; сводки за день; скрытие телефонов и ограничения каналов для менеджеров.
- Явные миграции, зависимости с хешами, приватные файлы, атомарные резервные копии, диагностика без изменений БД, отдельная служба с ограничением ресурсов.

## С чего начать

1. Прочитайте [DEPLOYMENT.md](DEPLOYMENT.md): установка на общий сервер и пределы изоляции.
2. При переносе версии 1.2 сначала следуйте [UPGRADE.md](UPGRADE.md). Существующий ключ `SESSION_ENCRYPTION_KEY` необходимо сохранить.
3. В боте откройте `/start` → «Прокси», загрузите и проверьте прокси. Если нужен IP сервера, владелец явно разрешает прямое подключение в настройках.
4. «Добавить аккаунты» → выберите QR, номера или файл. Подробнее — [docs/ACCOUNTS.md](docs/ACCOUNTS.md).
5. Добавьте каналы, снимите общую паузу, запустите небольшой тест. Состояние и выгрузки находятся в «Заданиях и отчётах».

После первой миграции включена общая пауза. Это позволяет проверить настройки до выхода аккаунтов в сеть.

## Локальная разработка

Целевая среда: Linux, Python 3.12+, PostgreSQL 16+. Сборка зависимостей зафиксирована для Python 3.12. Для другой версии Python сначала проверьте установку и тесты. Серверный процесс использует Linux `flock`; на Windows запускайте через WSL2. Редактировать проект можно в PyCharm.

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install --require-hashes -r requirements.txt
.venv/bin/python -m pip install -r requirements-dev.txt
cp .env.example .env
.venv/bin/python manage.py configure .env
# База и отдельная роль должны уже существовать.
.venv/bin/python manage.py migrate
.venv/bin/python doctor.py
.venv/bin/python -m app.main
```

Тесты используют вымышленные учётные данные и не подключаются к Telegram:

```bash
.venv/bin/python -m pytest -q
.venv/bin/python -m ruff check app tests scripts manage.py doctor.py
.venv/bin/python -m ruff format --check app tests scripts manage.py doctor.py
.venv/bin/python -m pip_audit -r requirements.txt --disable-pip --no-deps
```

Два теста миграции требуют отдельной тестовой PostgreSQL: задайте `TGVIEWER_TEST_DATABASE_URL`. Каждый тест создаёт случайную тестовую схему и удаляет только её. Не задавайте адрес рабочей базы. В `.github/workflows/check.yml` подготовлен CI с PostgreSQL 16; сам workflow из этого окружения не запускался.

## Устройство проекта

| Каталог | Назначение |
|---|---|
| `app/bot` | Экраны, права, ввод и команды бота |
| `app/services/runtime.py` | Единое владение подключениями, прокси, ожидание Telegram |
| `app/services/jobs.py` | Очередь, план результатов, контрольные точки и остановка |
| `app/services/onboarding.py` | QR, 2FA, очередь добавления и очистка секретов |
| `app/services/imports.py` | Ограниченный разбор файлов и ZIP без выполнения содержимого |
| `app/services/maintenance.py` | Расписания, копии, сроки хранения и фоновые проверки |
| `app/migrations.py` | Версионированное обновление схемы; запускается явно |
| `tests` | Проверки безопасности, исполнения, импорта и миграций |
| `scripts` | Установка, обновление и проверка восстановления |

Изменяйте прямые зависимости в `requirements.in` и `pyproject.toml`; пересобирайте `requirements.txt` через `pip-compile --generate-hashes --allow-unsafe --strip-extras requirements.in`. После обновления зависимостей повторяйте тесты и проверку уязвимостей.

## Что нужно знать о результате

Счётчик в отчёте отражает успешно обработанные запросы регистрации просмотра, а не гарантированный прирост публичного счётчика Telegram. Между ответом Telegram и записью контрольной точки остаётся небольшое окно при аварийном отключении: последняя порция может быть обработана повторно. Гарантии «ровно один раз» у этого API нет.

Локальные автоматические проверки перечислены в [docs/VERIFICATION.md](docs/VERIFICATION.md). Авторизация настоящего аккаунта, действующие прокси, нагрузка вашего сервера и полное восстановление реального дампа проверяются при развёртывании. Ни служба, ни аккаунты из этого пакета на ваш сервер автоматически не устанавливались.
